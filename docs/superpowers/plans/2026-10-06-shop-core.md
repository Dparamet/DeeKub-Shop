# deeKub Shop Core Implementation Plan

**Goal:** Finish signup/login, a searchable game shop, cart, persistent orders with mock payment, and role-protected product/order administration.

**Architecture:** Next.js owns pages and cookie-based Supabase Auth sessions. Go verifies bearer tokens with Supabase Auth's `/auth/v1/user` endpoint and reads roles from PostgreSQL; this also supports legacy signing keys without configuring a JWT secret. Go owns prices, stock, order transitions, and admin writes.

**Tech Stack:** Next.js 16.3.8, React 19.3.0, TypeScript 6, Supabase SSR, Go 1.25+, Gin, pgx, Supabase PostgreSQL.

**Spec:** `docs/superpowers/specs/2026-10-06-supabase-auth-orders-design.md`; the user approved this architecture and requested implementation on 2026-10-06. Execute inline in the existing feature branch.

## Global Constraints

- Payment and delivery remain simulated; demo keys cannot be redeemed.
- Keep the root `.env` and existing credentials private; use its existing `NEXT_PUBLIC_SUPABASE_*` names.
- No storefront admin link. `/admin` requires a verified login and database ADMIN role.
- Never accept role, user ID, totals, or payment success from the browser as authority.
- Reuse existing artwork; Loaded informs discovery, platform/region information and the purchase flow.
- Do not run or add tests without the user's request. Use formatting, type checking, lint and compilation to inspect implementation.
